# DVTrackingTutorial

A small CLD full-simulation tutorial for studying reconstruction of a two-track displaced vertex.

## Physics topology

Each event contains one truth displaced vertex at

    x = r_DV cos(phi)
    y = r_DV sin(phi)
    z = z_DV

where phi is random.

Two stable particles are produced from this common vertex:

    DV -> mu- + mu+

Both daughters have configurable momentum.

This is deliberately a **vertex/tracking gun**, not a physical two-body
decay of a parent particle. It is intended to isolate detector tracking and
vertexing performance before moving to a real physics sample.

Default values:

- r_DV = 100 mm
- z_DV = 0 mm
- p(mu) = 10 GeV
- opening parameter = 1 rad
- CLD geometry = CLD_o2_v07

## 1. Set up Key4hep

If you have already sourced the Key4hep environment you can simply do:

    source setup.sh

Otherwise `setup.sh` attempts to source the Key4hep nightly environment.

Check that it prints paths for:

    ddsim
    HepMC3-config
    DETECTOR

The generator build deliberately uses `HepMC3-config`, so it follows the
HepMC3 installation belonging to your active environment rather than a
hard-coded CVMFS path.

## 3. Build the HepMC3 generator

    ./build_generator.sh

For the environment tested while debugging this tutorial,
`HepMC3-config --version` returned 3.03.01 and the installation prefix
pointed to HepMC3 3.3.1.

The build command is essentially:

    g++ -std=c++17 generate_dv_sample.cpp \
        $(HepMC3-config --cflags) \
        $(HepMC3-config --libs) \
        -o generate_dv_sample

An rpath to the HepMC3 library directory is also added by the script.

## 4. Test generation only

Do this before running Geant4:

    ./test_generation.sh

It builds the generator if necessary and creates:

    test_dv.hepmc3

The file should start with native HepMC3 ASCII generated by
`HepMC3::WriterAscii`.

## 5. Generate a 10-event sample

    ./generate_dv_sample \
        --nev 10 \
        --radius 100 \
        --momentum 10 \
        --output dv_r100.hepmc3

Optional arguments are:

    --z Z_MM
    --opening ANGLE_RAD
    --seed INTEGER

## 6. Run CLD full simulation

First use only 10 events:

    ./run_fullsim.sh \
        dv_r100.hepmc3 \
        dv_r100_SIM.edm4hep.root \
        10

The script now passes the same requested event count directly to:

    ddsim --numberOfEvents 10

and checks that a non-empty output file was produced.

### Checkpoint

Do not move to reconstruction until this completes without a HepMC reader
error.

The previous failure looked like:

    ERROR::ReaderAsciiHepMC2: HEPMC3_ERROR parsing event information

That error should disappear because this version uses HepMC3 itself to
serialize the event.

## 7. Inspect the simulation file

    ./inspect_file.sh dv_r100_SIM.edm4hep.root

At this point we want to confirm that the MC particle and tracker
simulation-hit collections exist.

## 8. Run CLD tracking reconstruction

    ./run_reco.sh \
        dv_r100_SIM.edm4hep.root \
        dv_r100 \
        10

This invokes CLD reconstruction with:

    --trackingOnly
    --conformalTracking

and should produce:

    dv_r100_REC.edm4hep.root

The CLD ConformalTracking configuration includes its displaced tracking
stage.

## 9. Inspect reconstruction output

    ./inspect_file.sh dv_r100_REC.edm4hep.root

We are particularly interested in the reconstructed track collections,
including the refitted tracks and MC/reconstruction association
collections available in the active CLDConfig version.

## 10. Run one complete radius point

After the individual generation/fullsim/reco stages work:

    ./run_point.sh 100 10 10

Arguments are:

    ./run_point.sh RADIUS_MM N_EVENTS MOMENTUM_GEV

Outputs are organised under:

    samples/
    sim/
    reco/
    logs/

## 11. Radius scan

For a small debugging scan:

    NEVT=10 MOMENTUM=10 ./run_scan.sh

For a more meaningful sample:

    NEVT=1000 MOMENTUM=10 ./run_scan.sh

The configured radii are:

    1, 5, 10, 20, 30, 50, 75, 100, 150, 200, 300,
    400, 500, 750, 1000, 1250, 1500 mm

## Efficiency definitions

The eventual analysis should separate:

1. two-track efficiency

       epsilon_2trk = N(both truth daughters reconstructed) / N(generated DVs)

2. conditional vertex efficiency

       epsilon_vtx|tracks =
           N(matched reconstructed DVs) /
           N(events with both truth daughters reconstructed)

3. overall DV efficiency

       epsilon_DV =
           N(matched reconstructed DVs) /
           N(generated DVs)

This lets us distinguish tracking inefficiency from vertex-fitting
inefficiency.

## Plotting

`plot_efficiency.py` expects a CSV with:

    radius,n_gen,n_2tracks,n_vertex

and can be run with:

    python3 plot_efficiency.py efficiency.csv

The v3 plotter safely handles points with zero reconstructed two-track
events.

## Current boundary of this tutorial

The generation -> Geant4 -> CLD ConformalTracking chain is scripted here.

The final truth-matched two-track vertex fitting stage is intentionally not
hard-coded yet because its exact input collection/interface should be
matched to the EDM4hep collections produced by the active CLDConfig/Key4hep
release.

Once the 10-event reconstruction file is produced, run:

    ./inspect_file.sh dv_r100_REC.edm4hep.root

The resulting collection list is the right input for implementing the
truth matching and displaced-vertex fitter without guessing collection
names.

## Recommended debugging order

Always debug in this order:

    ./build_generator.sh
    ./test_generation.sh

    ./generate_dv_sample \
        --nev 10 --radius 100 --momentum 10 \
        --output dv_r100.hepmc3

    ./run_fullsim.sh \
        dv_r100.hepmc3 \
        dv_r100_SIM.edm4hep.root \
        10

    ./inspect_file.sh dv_r100_SIM.edm4hep.root

    ./run_reco.sh \
        dv_r100_SIM.edm4hep.root \
        dv_r100 \
        10

    ./inspect_file.sh dv_r100_REC.edm4hep.root

Only after all of those work should you use `run_point.sh` or `run_scan.sh`.


## v4 parent-particle fix

The displaced vertex now has an incoming generator-level parent particle
(PDG 9900012, status 2). Its four-momentum is exactly the sum of the two
daughter muon four-momenta. The parent therefore ends at the displaced
vertex and the vertex has the conventional graph topology

    X -> mu- + mu+

rather than a vertex with no incoming particle.

There is deliberately no separate production vertex for X in this minimal
test. This avoids introducing another source-only HepMC vertex while still
giving the displaced decay vertex an incoming edge.

`run_fullsim.sh` now also captures the ddsim log and returns failure if the
log contains a HepMC parsing failure or Geant4 run-abort message. The
existence of an EDM4hep ROOT file alone is no longer treated as success.
